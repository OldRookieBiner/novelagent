# v0.8.1 优化设计文档

> 项目删除修复 + 灵感页面模型选择器

## 一、项目删除修复

### 问题

`DELETE /api/projects/{id}` 返回 HTTP 500 Internal Server Error。

### 根因

`Project` 模型缺少 `WorkflowCheckpoint` 的级联删除关系。SQLAlchemy 在删除 Project 时尝试将 `workflow_checkpoints.project_id` 设为 NULL，但该列有 NOT NULL 约束，触发 IntegrityError。

### 方案

在 `Project` 模型中添加 `checkpoints` 关系，配置 `cascade="all, delete-orphan"`，与现有的 `outline`、`chapter_outlines`、`workflow_states`、`characters`、`relations` 保持一致。同时在 `WorkflowCheckpoint` 中将 `backref` 改为显式 `back_populates`，保持项目代码风格一致。

### 影响范围

- `backend/app/models/project.py`：添加 checkpoints 关系
- `backend/app/models/checkpoint.py`：`backref` → `back_populates`

## 二、灵感页面模型选择器

### 问题

灵感采集页面无法选择使用哪个已配置的 AI 模型来生成大纲，用户配置了多个模型但无从选择。

### 设计

在灵感面板底部操作栏添加模型选择器，位于「开始规划」按钮左侧。

#### 2.1 位置

底部操作栏，与「开始规划」按钮在同一行水平排列：

```
┌─ 底部操作栏 ──────────────────────────────────────┐
│  [🤖 AI 模型: DeepSeek-V3 (深度求索) ▼]  [✓ 开始规划 →] │
│                      确认后自动开始规划              │
└──────────────────────────────────────────────────┘
```

#### 2.2 组件

使用项目现有的 shadcn/ui `Select` 组件（`components/ui/select.tsx`）。

#### 2.3 数据来源

调用 `modelConfigsApi.list()` 获取当前用户的所有已启用模型配置，筛选 `is_enabled === true` 的配置。

#### 2.4 下拉选项结构

按提供商分组，每个可选项对应一个**具体模型**：

- **single 类型配置**：直接作为一条可选项，显示为 `model_name`
- **coding_plan 类型配置**：展开 `models` 数组，仅显示 `is_enabled === true` 的 model，每个 model 作为一个可选项

分组标签（提供商名）为灰色、不可点击，仅作视觉分组。

示例下拉：

```
选择 AI 模型
──────────────────────────
 DeepSeek (深度求索)        ← 分组标签，不可选
   ✓ DeepSeek-V3     [默认]  ← 可选项（model_config_id=3, model_name="deepseek-v3"）
     DeepSeek-R1            ← 可选项（model_config_id=3, model_name="deepseek-r1"）
     DeepSeek-Coder         ← 可选项（model_config_id=3, model_name="deepseek-coder"）
 OpenAI                     ← 分组标签，不可选
     GPT-4o                 ← 可选项（model_config_id=1, model_name="gpt-4o"）
     GPT-4o-mini            ← 可选项（model_config_id=5, model_name="gpt-4o-mini"）
 Anthropic                  ← 分组标签，不可选
     Claude 4 Sonnet        ← 可选项（model_config_id=7, model_name="claude-sonnet-4-20250514"）
```

#### 2.5 默认值

- 优先选中用户设为 `is_default === true` 的模型配置
- 若该配置是 coding_plan 类型，默认选中其 models 数组中的第一个模型
- 无默认配置时显示 placeholder「请选择模型」

#### 2.6 传递给后端

选中后传递 `model_config_id` 和 `model_name` 给后端：

1. 通过 `collectedInfoApi.update()` 将选中的模型信息保存
2. `OutlineProgressDialog` 启动工作流时将 `llm_config_id` 传递给 SSE 流式 API
3. 后端 LangGraph 节点通过 `get_llm_service_from_config(model_config_id)` 使用指定模型

后端已有完整的 `llm_config_id` 支持链路：

```
workflow.py → build_initial_state(llm_config_id=request.llm_config_id) → NovelState.llm_config_id
→ deps.py → get_llm_for_user(user_id, settings, db, llm_config_id)
→ get_llm_service_from_config(model_config) → LLMService
```

#### 2.7 底部显示

选中后在底部选择器中显示：`模型名 (提供商)`

例：`DeepSeek-V3 (深度求索)` 或 `GPT-4o (OpenAI)`

### 影响范围

- `frontend/src/components/workbench/planning/InspirationPanel.tsx`：添加模型选择器 UI + 状态管理 + 数据获取逻辑
- `frontend/src/components/workbench/planning/OutlineProgressDialog.tsx`：接收 `modelConfigId` 参数并传递给工作流 API
- `frontend/src/lib/workflowApi.ts`：`runWorkflow` 方法支持 `llmConfigId` 参数

### 不涉及

- 不修改 LangGraph 工作流节点（已有完整 llm_config_id 支持）
- 不修改设置页面模型配置管理
- 不修改后端 API 端点
- 不增加数据库迁移

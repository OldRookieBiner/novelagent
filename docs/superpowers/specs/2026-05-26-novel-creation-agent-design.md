# AI 小说创作智能体 — 设计规格文档

> 日期：2026-05-26
> 项目：NovelAgent 重构
> 方案：Fork novelagent + 重写 Agent 层

## 1. 背景与目标

### 1.1 当前问题

NovelAgent 当前是一个 AI 小说**生成工作流**——固定管道式执行（大纲→角色→关系→章节纲→正文→审核），存在三个根本性问题：

1. **写作质量无保障**：审核节点只做 LLM 打分，没有伏笔追踪、风格漂移检测、角色知识边界约束、问题链闭环等机制
2. **知识库是僵化的**：阶段 1 生成设定后几乎不再变化，写作中涌现的新灵感和发现的设定错误无法回写到知识库
3. **没有创作智能体的元认知**：系统不知道"写了什么、有什么问题、下一步该注意什么"，只是机械执行节点

### 1.2 目标

将 NovelAgent 从"AI 小说生成工作流"转型为"AI 小说创作智能体"：

- **写作质量为核心**：引入 novelskills 项目的完整写作方法论（逆向规划、伏笔分级回收、角色知识边界、风格漂移检测、深度审查等）
- **活知识库**：知识库持续生长，写作中可随时丰富和修正，变更前自动评估影响范围
- **智能体元认知**：感知→决策→执行→自检的闭环，主动预警，按需检索

### 1.3 方案选择

| 方案 | 描述 | 结论 |
|------|------|------|
| A（采纳） | Fork novelagent，保留前端框架+Docker+认证+SSE+API层，删除 `agents/` 从零重写，扩展数据模型和前端 | 复用 ~40% 基础设施，精力集中在 Agent 层 |
| B | 在 novelagent 主分支逐步替换 | 旧新代码长期共存，中间状态不稳定 |
| C | 全新项目 | 基础设施重建浪费 1-2 个月，与核心能力无关 |

### 1.4 兼容性

不需要兼容旧项目数据。可大胆修改 NovelState、DB Schema、API。

### 2.1 Agent 层双轨设计

| | 主写作循环 (StateGraph) | 自由操作 Agent (ReAct) |
|---|---|---|
| 职责 | 推进写作流程：从章节点到正文到自检 | 处理用户即时干预：改设定、查伏笔、问进度 |
| 触发 | 用户点"继续写作"或"写下一章" | 用户在 AI 侧栏输入指令 |
| 共享 | 同一套知识库服务和数据层 | 同一套知识库服务和数据层 |
| 交互 | SSE 流式推送进度，前端实时展示 | 对话式交互，工具调用可见 |

两套 Agent **共享知识库服务层**——主写作循环写入的追踪数据，自由操作 Agent 可查询；自由操作 Agent 的修改，主写作循环下次执行时会感知到。

### 2.2 LangGraph 框架

保留 LangGraph，从管道式工作流升级为智能体状态机：

- **主写作循环**：`StateGraph`，~22 个节点，条件路由（深度审查每 5 章触发、伏笔检查决定是否预警）
- **自由操作**：`create_react_agent` + 认知型 tools，不再是 CRUD 操作
- **检查点**：保留 WorkflowCheckpoint，支持暂停/恢复

## 3. 创作流程设计

### 3.1 核心理念：活知识库

知识库不是阶段 1 一次性生成的静态文档，而是从第一句创意到最后一章写完**持续生长**的活系统。

```
创意对话 → 知识库初建（够用即可） → 结构设计 → 写作
     ↑           ↑                       ↑           ↑
     对话式      初版是最小可用版本        结构设计时   写作时发现新细节
     探索创意                            可能补充设定 反哺知识库
```

阶段之间没有硬边界，但有**进展里程碑**——知识库达到最小可用 → 结构设计可以开始 → 结构确认 → 写作可以开始。用户可以在任何里程碑之间自由来回。

### 3.2 阶段 1：创意孵化 + 知识库初建

**不是表单收集，是对话式创意孵化。** 用户说一句话创意，Agent 生成 2-3 个方向，用户选一个，再一起细化故事种子。

```
用户自由表达想法（一句话、一段描述、甚至一个氛围）
      ↓
inspiration_dialogue_node    对话式孵化
  ├─ 基于用户创意生成 2-3 个故事方向
  ├─ 每个：一句话 hook + 核心冲突 + 开场场景
  ├─ 用户选择或自己改一个
  └─ 追问关键信息（逐一引导，不一次全问）
      ↓
story_seed_node              生成故事种子（一段激发灵感的叙述，不是字段表）
      ↓
outline_generation_node      生成大纲（标题/概述/情节节点/伏笔地图）
      ↓
world_setting_node           生成世界观（🔴🟡🟢分级设定 + 关键地点）
      ↓
character_generation_node    生成角色（含知识边界、对话样本）
      ↓
relation_generation_node     生成关系图谱
      ↓
style_setup_node             设定风格约束（禁忌词/风格锚点/禁用句式）
      ↓
foreshadowing_plan_node      规划伏笔-回收地图
      ↓
  用户确认（可修改任何设定）
```

知识库初建是**最小可用版本**——核心冲突、主要角色、世界基调、风格方向。不需要一次性生成所有细节，缺失的部分留待写作中自然填充。

`inspiration_dialogue_node` 是多轮对话节点——Agent 和用户来回几轮后，提炼信息写入 state，再进入后续节点。通过 `waiting_for_confirmation` 机制实现，确认类型为 `inspiration_dialogue`。

### 3.3 阶段 2：结构设计——逆向规划

```
question_chain_design_node  问题链设计（龙头凤尾 + 情节块的问题链）
      ↓
plot_blocks_node            情节块展开
  每个情节块：回答旧问题 / 提出新问题 / 必须事件 / 情绪基调
      ↓
subplot_network_node        支线网络（多线叙事的支线登记和交汇规划）
      ↓
rhythm_curve_node           预期节奏曲线（每块情绪基调映射，检查单调段）
      ↓
chapter_count_estimate_node 章节数估算
      ↓
  用户确认结构
```

### 3.4 阶段 3：逐章写作——感知→决策→执行→自检

```
┌──────────────────────────────────────────────────┐
│                                                    │
│  context_assembly_node（感知）                     │
│    ├─ 加载当前情节块目标 + 风格约束                 │
│    ├─ 语义检索相关设定和角色（按需，不是全文）       │
│    ├─ 伏笔检查：哪些待回收伏笔可在这章回收？        │
│    ├─ 问题链检查：当前情节块要回答什么旧问题？       │
│    └─ 长篇：加载跨卷追踪相关条目                    │
│         ↓                                          │
│  chapter_planning_node（决策）                     │
│    ├─ 输出章节点：因果链/钩子/场景规划              │
│    ├─ 明确：回答哪个旧问题/提出什么新问题           │
│    ├─ 标记：涉及角色/涉及设定/待回收伏笔            │
│    └─ 用户可确认/修改                              │
│         ↓                                          │
│  chapter_writing_node（执行）                      │
│    ├─ 基于章节点+上下文+风格约束写正文              │
│    └─ 分场景写作，每场景做连贯性检查                │
│         ↓                                          │
│  post_write_update_node（自检——13项子任务）        │
│    ├─ character_consistency_check   角色一致性自查  │
│    ├─ timeline_update               追加时间线      │
│    ├─ foreshadowing_update          更新伏笔表      │
│    ├─ plot_question_update          更新问题链      │
│    ├─ dynamic_setting_update        更新动态设定    │
│    ├─ style_taboo_check             禁忌词快查      │
│    ├─ style_stats_update            风格统计        │
│    ├─ subplot_update                更新支线网络    │
│    ├─ dialogue_sample_extract       对话样本提取    │
│    ├─ scene_list_update             更新场景清单    │
│    ├─ timeline_compression          时间线压缩      │
│    └─ retrieval_index_mark          标记待索引内容  │
│         ↓                                          │
│  deep_review_node（每5章触发）                     │
│    ├─ 情节一致性 / 伏笔追踪 / 节奏分析             │
│    ├─ 设定违反检查 / 风格漂移检测 / 支线追踪        │
│    └─ 输出审查报告 → 主Agent据此修改               │
│         ↓                                          │
│  → 下一章（回到 context_assembly_node）            │
└──────────────────────────────────────────────────┘
```

### 3.5 阶段 4：全书修订

```
structural_review_node      结构完整性（伏笔闭环/问题链闭环/时间线一致性/支线闭环）
      ↓
character_arc_review_node   角色弧与风格一致性（弧线验证/逐章风格检查/开场钩子闭环）
      ↓
final_polish_node           最终润色 + 生成设定百科（可选）
```

## 4. 知识库变更影响评估

### 4.1 设计动机

已发布章节不可轻易修改（连载小说的商业约束）。修改知识库设定前，必须先评估影响范围，让作者根据评估结果决定改不改、怎么改。

### 4.2 评估流程

```
1. 变更提案（不是直接改）
   用户/Agent 发现需要修改某个设定
      ↓
   impact_assessment_node（影响评估节点）
      ├─ 语义检索：搜索所有已写章节中引用该设定的段落
      ├─ 分级统计：
      │   ├─ 🟢 不影响（设定变更与已有内容无交集）
      │   ├─ 🟡 轻微影响（细节矛盾，读者不易察觉）
      │   ├─ 🟠 中度影响（逻辑不一致，细心读者会发现）
      │   └─ 🔴 严重影响（核心情节与设定直接矛盾）
      ├─ 逐章列出受影响段落 + 影响程度 + 具体矛盾说明
      ├─ 统计：影响 N 章 / M 段 / 其中 P 段为🔴严重
      └─ 生成影响评估报告

2. 作者决策
   基于评估报告，作者有三种选择：

   a) 按原方案修改 → 执行变更 → 按影响等级处理受影响章节
   b) 调整修改方案（减少影响范围）→ 重新评估 → 循环直到满意
   c) 放弃修改 → 不改知识库，后续写作中规避 → 标记"⚠️ 已知矛盾"

3. 执行（仅当作者选择修改时）
   按影响等级分级处理：
   ├─ 🟢 不处理
   ├─ 🟡 标记"待修正"，不阻塞写作
   ├─ 🟠 提示作者，确认后可修改或搁置
   └─ 🔴 必须处理：修改已发布章节 / 调整后续结构 / 或放弃修改
```

### 4.3 关键价值

把"改还是不改"从全有或全无的二元选择，变成可量化、可调整的决策过程。鼓励小修改优先——如果小调整能把影响从🔴12章降到🟡1章，作者大概率选小调整。

## 5. 知识库数据结构

### 5.1 项目层

```
Project
├── story_seed              故事种子（创意对话沉淀）
├── style_constraints_id    → StyleConstraints

```

### 5.2 设定层

```
WorldSetting
├── core_concept            核心理念
├── tiered_settings         分级设定 JSON
│   ├── 🔴 不可违反
│   ├── 🟡 可突破有代价
│   └── 🟢 装饰性
└── key_locations           关键地点 JSON

├── 核心动机 / 核心冲突 / 人物弧

├── speech_style            说话风格

└── key_relationships       关键关系

├── 关系类型 / 方向 / 信任度
└── 发展趋势

StyleConstraints
├── taboo_words             禁忌词列表
├── forbidden_patterns      禁用句式
├── style_anchor            风格锚点（用户贴的参考文段）
└── abstract_rules          抽象风格规则
```

### 5.3 结构层

```
PlotBlock
├── title
├── questions_to_answer     要回答的旧问题

├── chapter_start / chapter_end

```

## 6. 自由操作 Agent

### 6.1 感知类工具

| 工具 | 功能 | 场景 |
|------|------|------|
| `knowledge_search` | 语义检索知识库 | "主角的魔法有什么限制？" |
| `foreshadowing_check` | 检查伏笔状态 | "有哪些伏笔还没回收？" |
| `consistency_check` | 一致性检查 | "主角第5章说不知道，第8章却提到了" |
| `style_analysis` | 风格分析+漂移检测 | "最近几章对话是不是太多了？" |
| `progress_report` | 写作进度报告 | "写到哪里了？" |
| `rhythm_analysis` | 节奏分析 | "最近几章是不是太平了？" |

### 6.2 修改类工具（带影响评估）

| 工具 | 功能 | 说明 |
|------|------|------|
| `propose_setting_change` | 提议修改知识库设定 | 自动触发影响评估，返回报告给用户决策 |
| `propose_outline_adjustment` | 提议调整结构 | 评估对已写章节和伏笔的影响 |
| `propose_chapter_rewrite` | 提议重写章节 | 标记旧版 → 重写 → 更新追踪文件 |

### 6.3 创作辅助工具

| 工具 | 功能 |
|------|------|
| `writer_block_assist` | 卡文助手：2-3个写作方向（场景建议+可回收伏笔+问题链） |
| `suggest_foreshadowing` | 建议伏笔埋设（基于当前情节块+已有伏笔地图） |
| `suggest_plot_twist` | 建议情节转折（基于节奏曲线+角色弧+待回收伏笔） |
| `expand_world_setting` | 扩展世界观（自动评估影响） |

### 6.4 主动预警

写作流程中 Agent 可主动推送预警（通过 SSE）：

- 伏笔超期：🟡待回收伏笔超过预期回收位置
- 风格漂移：最近 10 章统计偏离基准 >25%
- 节奏单调：连续 3+ 章相同情绪
- 设定冲突：写作中产生的新内容与🔴设定矛盾

前端以非阻塞方式提示，作者可选择处理、忽略、或让 Agent 自动调整。

## 7. 前端交互设计

### 7.1 整体布局

### 7.2 标签页设计

4 个标签页，左栏章节列表始终可见：

- **写作**：主区域显示章节点（含当前章节上下文）+ 正文编辑器
- **知识库**：主区域显示设定集浏览（世界观/角色/关系/风格约束/故事种子），左侧有知识库导航
- **结构**：主区域显示情节块列表 + 问题链状态 + 支线网络 + 预期节奏曲线
- **追踪**：主区域显示伏笔地图/时间线/风格统计/场景清单，左侧有追踪导航

### 7.3 左栏：章节列表

- 按情节块分组显示章节
- 状态标识：🟢已写 / 🔵写作中 / ○待写
- 当前选中章节高亮
- 点击切换章节，主区域同步更新

### 7.4 章节点

章节点承载当前章节的全部上下文，展示在正文上方：

- 问题链：回答的旧问题 / 提出的新问题
- 待回收伏笔（含超期预警）
- 涉及角色（含知识边界摘要）
- 涉及设定（含分级标识）
- 场景规划
- 确认/修改按钮

### 7.5 右栏：智能体对话

- 创意对话贯穿全程，不局限于灵感阶段
- 预警推送嵌入对话流（非阻塞）
- 影响评估报告嵌入对话流
- 用户可随时发指令（改设定、查伏笔、问进度等）

### 7.6 底栏：进度仪表盘

- 节奏曲线（迷你折线图）
- 伏笔健康度（待回收/超期数）
- 风格状态（稳定/漂移）
- 当前情节块
- 整体进度

## 8. 语义检索服务

### 8.1 架构

```
RetrievalService
  输入：自然语言查询 + 可选章节范围
  输出：按相关度排序的知识片段列表

  FAISS 索引（bge-m3 模型）× 0.6 + BM25 索引（jieba 分词）× 0.4
  → 混合排序 → 去重 + 截断 → 返回 top-k
```

### 8.2 检索触发时机

| 时机 | 触发方式 | 查询来源 |
|------|----------|----------|
| 写章前上下文组装 | `context_assembly_node` 自动 | 章节点的"涉及角色"+"涉及设定" |
| Agent 自由对话 | 用户提问 | 自然语言问题 |
| 变更影响评估 | `impact_assessment_node` 自动 | 变更内容的语义描述 |

### 8.3 索引来源

- **全局索引**：世界观 + 角色 + 关系 + 风格约束 + 故事种子 + 追加设定
- **卷索引**（大项目）：时间线 + 伏笔 + 场景清单

### 8.4 索引更新

- 全量重建：每 5 章，由 `post_write_update_node` 触发
- 增量标记：非重建章节的变更标记"待索引"，下次 rebuild 时纳入
- 大项目双层级：优先搜当前卷索引，不足时补充全局索引

### 8.5 与 novelskills search.py 的关系

核心逻辑（FAISS+BM25 混合检索、bge-m3 模型、jieba 分词）直接复用 search.py，数据源从 Markdown 文件改为 DB 查询。

## 9. 超长篇卷管理

### 9.1 触发切卷

- 情节块自然结束
- 容量提示（非首卷超过上卷 1.5 倍章节数，首卷超过 120 章）
- 用户手动说"切卷"

### 9.2 切卷流程

```
volume_transition_node:
  1. 收尾检查：当前卷🟡待回收伏笔 → 询问是否升级为长期伏笔
  2. 角色状态快照 → 写入 Volume.character_snapshot
  3. 逐卷修订 → 对当前卷执行阶段4三轮修订
  4. 跨卷追踪写入：
     ├─ 长期伏笔升级到 CrossVolumeForeshadowing
     ├─ 跨卷支线升级到 CrossVolumeSubplot
     ├─ 角色变化日志追加到 CharacterChangeLog
     └─ 时间线总览追加一行
  5. 检索索引：当前卷 rebuild + 全局 rebuild
  6. 规划新卷结构
  7. 创建新卷记录（Volume + 章节偏移量）
```

### 9.3 双层级检索

查询时先搜当前卷索引 → top-k 结果，不足时补充全局索引 → 合并去重。

### 9.4 章节双编号

- 列表/文件名：卷内编号（第1章、第2章...）
- 正文标题：全局连续编号（第95章）
- 偏移量 = Volume.chapter_offset + 卷内编号

## 10. 分阶段实施计划

### 阶段 1：创作智能体骨架（4-5 周）

**目标**：重写 Agent 层 + 数据模型，跑通最小写作闭环

- 删除旧 `agents/` 目录，从零重写
- 实现 ~20 个 LangGraph 节点（创意孵化 → 结构设计 → 逐章写作 → 写后自检）
- 新增 9 个核心数据模型（WorldSetting / StyleConstraints / PlotBlock / PlotQuestion / Subplot / Foreshadowing / TimelineEntry / StyleSnapshot / SceneEntry），超长篇和变更追踪模型在后续阶段加入
- 重写 NovelState
- 前端最小改动：重写 WorkbenchLayout（三栏+标签页+底栏）+ 章节列表 + 章节点确认

**交付标准**：能从创意对话走到逐章写作，写后自检自动执行

### 阶段 2：知识库 + 智能体交互（3-4 周）

**目标**：活知识库 + 自由操作 Agent + 变更影响评估

- 知识库服务层（KnowledgeBaseService / ForeshadowingEngine / StyleAnalyzer / TimelineService）
- 重写自由操作 Agent（感知类/修改类/创作辅助工具）
- 变更影响评估（impact_assessment_node + SettingChange 模型）
- 前端：知识库/追踪/结构标签页 + 智能体对话面板升级 + 底栏仪表盘

**交付标准**：用户可以在写作过程中自由修改知识库，系统自动评估影响

### 阶段 3：语义检索 + 写作质量打磨（3-4 周）

**目标**：按需检索替代全文加载，打磨写后自检和深度审查

- 语义检索服务（RetrievalService，复用 search.py 核心逻辑）
- context_assembly_node 集成检索
- 写后自检打磨（角色知识边界检测、伏笔三级递进、风格漂移检测）
- 深度审查打磨（时间线矛盾、伏笔超期、节奏单调、设定违反、POV 审查）
- 主动预警机制（SSE 推送到前端）

**交付标准**：写作质量自检完整闭环，检索按需加载

### 阶段 4：超长篇 + 全书修订（3-4 周）

**目标**：支撑 300 万字级创作 + 完整修订流程

- 卷管理（Volume 模型 + 切卷流程 + 双层级检索 + 跨卷追踪）
- 全书修订（结构完整性 → 角色弧与风格一致性 → 最终润色）
- 前端：卷管理面板 + 修订报告面板

**交付标准**：能支撑超长篇创作，全卷修订完整可用

### 总预估

13-17 周（约 3-4 个月），各阶段严格串行，每阶段交付后可独立使用。

## 11. 不可违反规则

- 伏笔至少出现 2 次（暗示→强化）才能回收揭示
- 角色不得说出其知识边界之外的信息
- 🔴 设定不得违反（除非有明确铺垫的 🟡 突破）
- 每章必须回答一个旧问题或提出一个新问题（或两者）
- 章节点的"涉及角色""涉及设定""本章产生的钩子"字段不可省略
- 大项目：切卷时未回收的卷内伏笔必须决定去向
- 知识库变更必须先评估影响，不能直接修改

## 12. 质量预警信号

- 连续 2 章没有推进问题链
- 伏笔在预期回收位置后 2 个情节块仍未回收
- 时间线时序矛盾
- 风格约束连续 3 次违反
- 连续 3 章相同情绪且无预期节奏变化
- 角色行为与核心动机矛盾且无铺垫
- 支线在交汇点后 2 个情节块仍未交汇
- 大项目：跨卷支线交汇点后 2 卷未交汇；角色跨卷状态跳变无铺垫；长期伏笔预期回收卷后 2 卷未回收

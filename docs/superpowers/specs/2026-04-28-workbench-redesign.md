# 工作台页面重设计文档

## 概述

**版本**: v0.8.0
**日期**: 2026-04-28
**目标**: 重构前端工作台页面，采用 Tab 分组布局，优化用户创作体验

### 核心问题

1. **步骤流程割裂** - 当前步骤导航模式导致用户在不同阶段间切换不自然
2. **人物设定/关系规划页面空白** - 缺少对应的渲染逻辑
3. **功能入口混乱** - 新增功能后，左侧功能菜单显得杂乱无序
4. **审核与写作分离** - AI助手功能重复，审核流程独立导致切换成本高

### 解决方案

采用 **Tab 分组 + 功能菜单** 的工作台布局：
- 取消步骤概念，改为功能模块自由切换
- Tab 分组：规划 / 创作 / 审核
- 合并审核功能到写作页面的AI助手

## 各页面设计

### 1. 规划 Tab

#### 1.1 灵感页面

**布局**: 三栏布局（左侧进度提示 + 中间表单 + 右侧AI助手）

**表单字段**:
- 基本信息：小说标题、类型、目标读者、预期篇幅、写作风格
- 核心概念：一句话概述、核心主题
- 风格偏好：叙事风格、情感基调（Tag选择）
- 主角设定：姓名、年龄、职业、性别、性格特点、核心目标、内心困境、成长弧线
- 反派设定：姓名、身份、势力、与主角关系、动机、手段
- 主线剧情：开端、核心冲突、结局走向
- 支线剧情：可添加多条
- 世界观设定：可展开的多层设定

**特性**:
- 进度指示器显示完善度
- 各区块AI辅助按钮
- 自动保存

#### 1.2 人物页面

**布局**: 两列大卡片网格

**卡片内容**（每张卡片约 400x320px）:
- 大头像（60x60）+ 姓名
- 角色定位 Badge（主角/反派/配角/次要）
- 性格描述（2-3行）
- 核心动机
- 口头禅/习惯动作
- 背景故事（截断显示）
- 关系数量 Badge
- 编辑/删除按钮

**交互**:
- 点击卡片进入详情编辑
- 添加新人物卡片（虚线边框）

#### 1.3 关系页面

**布局**: 列表/表格形式

**表格列**:
- 人物A（头像+姓名）
- 关系类型（信任/敌对/感情/合作/利用/陌生）
- 人物B（头像+姓名）
- 当前状态
- 信任度（0-100 进度条）
- 操作（编辑/删除）

**特性**:
- 关系类型筛选
- 人物搜索
- 颜色编码关系类型

---

### 2. 创作 Tab

#### 2.1 小说大纲页面

**布局**: 左侧菜单 + 中间编辑器 + 右侧AI助手

**编辑内容**:
- 小说标题
- 一句话简介
- 故事概述（大文本框）
- 主要情节节点（可添加/删除/排序）
- 章节数量建议

**AI助手**:
- 显示优化建议
- 一键优化按钮
- 对话输入框

#### 2.2 章节大纲页面

**布局**: 三栏布局（与写作页面相同）
- 左侧：章节列表（180px）
- 中间：章节大纲表单
- 右侧：章节详情面板（320px）

**章节列表**:
- 编号 + 章节名
- 完成状态指示
- 点击选择

**中间表单**:
- 章节标题
- 章节摘要
- 主要情节点（可添加多条）
- 预估字数
- 保存/生成按钮

**右侧详情**:
- 场景设定
- 涉及人物
- 情节概要
- 冲突与结局
- 写作状态

#### 2.3 写作页面（含审核功能）

**布局**: 三栏布局
- 左侧：章节列表（180px）
- 中间：写作编辑器
- 右侧：AI助手面板（350px）

**AI助手面板（双Tab）**:
- Tab 1: 写作辅助
  - 情节建议
  - 续写建议
  - 角色提示
  - 用户输入框
- Tab 2: 质量检测（原审核功能）
  - 整体评分
  - 分项评分（情节连贯性、人物塑造、文笔表达、节奏把控）
  - 问题列表
  - 改进建议
  - 采纳/修改按钮

## 实现策略

采用 **新建页面 + 逐步迁移** 策略：

1. 创建 `ProjectWorkbench.tsx` 新页面
2. 逐步迁移各功能模块
3. 测试完成后切换路由
4. 删除旧页面

---

## 迁移计划

### Phase 1: 框架搭建
- 创建工作台布局组件
- 实现 Tab 导航
- 实现左侧功能菜单

### Phase 2: 规划模块迁移
- 灵感采集页面
- 人物管理页面（大卡片布局）
- 关系管理页面（列表布局）

### Phase 3: 创作模块迁移
- 小说大纲页面
- 章节大纲页面（三栏布局）
- 写作页面（含合并的AI助手）

### Phase 4: 切换与清理
- 路由切换
- 删除旧页面
- 清理未使用组件

## 风险与注意事项

1. **渐进式迁移** - 保持旧页面可用，避免影响现有功能
2. **组件复用** - 尽量复用现有组件，减少重写
3. **状态管理** - 注意新旧状态管理的兼容性
4. **测试覆盖** - 每个模块迁移后进行完整测试
